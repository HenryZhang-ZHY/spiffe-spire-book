# 术语表

## Access Control（访问控制）

一种规范资源访问的方法，同时涵盖身份认证与授权两个环节。

## ACLs (Access Control Lists)（访问控制列表）

一组规则，用于指定哪些用户或系统被授予访问特定对象的权限，以及允许对给定对象执行哪些操作。

## Active Directory

由微软为 Windows 域网络开发的目录服务。

## Agile（敏捷开发）

一组软件开发实践，通过迭代流程而非传统的瀑布流程，帮助团队更快地交付应用程序。

## API (Application Programming Interface)（应用程序编程接口）

由服务或应用程序提供的一组函数，作为抽象层供其他服务调用。

## API Token（API 令牌）

一个通用术语，指用于对 API 进行身份认证或访问 API 的服务唯一标识符。

## Attestation（验证）

断言实体的特定属性。在 SPIRE 的语境下，指断言节点或工作负载属性的过程。

## Auditing（审计）

用于检查和审查流程或系统的一组程序，以确保其符合合规性要求。

## Authentication（身份认证）

验证人类用户或系统身份的过程，核心在于回答“你是谁？”。

## Authorization（授权）

确定人类用户或系统对某项资源所拥有权限的过程，核心在于回答“你可以访问什么？”。

## Blast Radius（爆炸半径）

密钥泄露或错误配置问题可能波及的影响范围。

## BSD

伯克利软件发行版（Berkeley Software Distribution）。

## Certificate Authority (CA)（证书颁发机构）

负责签发数字证书的实体。

## Certificate Transparency（证书透明度）

一项互联网安全标准及开源框架，用于监控和审计数字证书。

## CI/CD (Continuous Integration/Continuous Deployment)（持续集成/持续部署）

一组工具和实践，通过在开发流水线中引入自动化，使开发团队能够频繁地对应用程序和系统进行变更。

## CLI（命令行界面）

Command Line Interface（命令行界面）；一种接收文本输入以执行操作系统功能的程序。

## Cloud (also Cloud computing)（云 / 云计算）

一种按需提供计算能力和存储资源的模式，允许用户根据自身需求从供应商提供的资源池中按需使用资源。在此过程中，部分管理职责也随之委托给了供应商。

## Cloud-aware or Cloud native（云感知 / 云原生）

专为在云平台上运行而设计的应用程序。云原生设计模式能够在分布式系统环境中实现水平扩展、便捷迁移以及高弹性。

## Common Name (CN)（通用名称）

证书中的一个字段，通常用于指定主机或服务器的身份。

## Container（容器）

一种软件单元，将代码及其所有依赖项打包在一起，使应用程序能够从一个计算环境快速、可靠地迁移到另一个计算环境并运行。

## Credential provisioning（凭据签发）

为服务或系统生成和/或签发凭据的过程。

## Cryptographic identities（密码学身份）

实体可用于通过密码学身份认证协议证明自身身份的一段数据，例如 X.509 证书。

## Data store（数据存储）

用于存储和管理数据集合的存储库。

## Denial of Service (DoS)（拒绝服务）

一种网络攻击类型，攻击者试图使服务或网络对其预期用户不可用。

## DevOps

工具与实践的结合，使组织能够以高速度交付应用程序，并赋能团队负责服务从开发到运维的整个生命周期。

## DNS (Domain Name Service)（域名服务）

一种面向计算机、服务或其他资源的分层、去中心化命名系统。

## Encryption（加密）

使用算法对信息进行编码、将原始明文转换为另一种称为密文的形式的过程，旨在保护信息的机密性，防止未经授权的第三方获取。

## Federation（联邦）

多个自治域的联合。当两个域实现联邦化时，意味着用户或服务在一个域完成身份认证后，即可访问另一个域中的资源，而无需再次经历特定于该域的身份认证流程。

## Firewall（防火墙）

用于管控网络流量的硬件或软件设备，最常用于创建允许/拒绝规则以管理实体之间的连接。

## Four eyes principle（四眼原则）

一种要求个人所执行的操作必须由第二位独立人员进行审查的机制。

## GDPR (General Data Protection Regulation)（通用数据保护条例）

欧盟颁布的关于数据保护和隐私的法规。

## gRPC

由 Google 开发的现代开源高性能远程过程调用（RPC）框架。

## Hardened（加固的）

系统经过一系列增强安全性的步骤后所达到的状态。这些步骤可能包括打补丁和调整配置等。

## Hardware Security Module (HSM)（硬件安全模块）

一种专用的密码学处理器，旨在管理和保护敏感密钥，并为数字签名及其他密码学功能提供加密和解密能力。

## High Availability（高可用）

系统在面对故障时保持弹性的特性，能够提供接近 100% 的服务正常运行时间。这一特性通过软件和硬件冗余实现，使系统在发生故障时仍能保持可用。

## HTTPS

超文本传输安全协议（Hypertext Transfer Protocol Secure），是 HTTP 协议的安全通信扩展，使用 TLS 建立安全连接。

## Human-in-the-loop systems（人机协同系统）

需要人工参与决策和操作执行的系统，例如手动工作流或人工审批。

## Interoperability（互操作性）

即使部署在不同平台或采用不同语言开发，系统仍能与其他系统进行交互的能力。

## IP (Internet Protocol)（互联网协议）

用于在网络中将数据从一台计算机发送到另一台计算机的协议或规则集。

## IPC (Inter-process Communication)（进程间通信）

操作系统提供的一种机制，用于允许进程之间相互通信。

## JWT (JSON Web Tokens)

一种开放的行业标准（RFC 7519）方法，用于在双方之间安全地表示声明（claims）。

## JWT-SVID

SPIFFE 规范中基于令牌的 SVID，旨在跨 L7 边界提供身份断言。JWT-SVID 是在标准 JWT 令牌基础上附加了一些额外限制的令牌。

## Kerberos

一种基于票据的身份认证协议，允许计算机在不受信任的网络中以安全的方式相互证明身份。

## Kernel（内核）

操作系统的核心部分，负责管理内存、CPU 和设备操作。

## Key Management Service (KMS)（密钥管理服务）

用于管理密码学密钥的系统，涵盖密钥的生成、交换、存储和吊销。

## Kill chain（攻击链）

指代网络攻击不同阶段的概念，即攻击者渗透系统所经历的一系列步骤。

## Kubernetes

一种容器编排系统。

## L3/L4

OSI 网络模型中的网络层（L3）和传输层（L4）。

## L7

OSI 网络模型中的应用层。

## Lead time reduction（前置时间缩短）

开发、测试并将应用程序部署到生产环境所需的时间。

## Legacy（遗留系统）

过时的技术和基础设施，通常难以维护，或难以与现代技术协同工作。

## Linux

基于 Linux 内核的一系列开源操作系统。

## Logging（日志记录）

将系统运行期间发生的事件记录在案的过程。

## Man-in-the-middle（中间人攻击）

一种攻击方式，攻击者在通信双方之间秘密截获通信内容，从而窃取或篡改敏感信息。

## Memory Leak（内存泄漏）

当不再需要的内存未被释放时发生的问题。

## Metering（计量）

收集服务或微服务在资源利用率方面的使用信息的过程，通常用于执行配额限制或进行资源管理。

## Merkle Tree（默克尔树）

一种基于哈希的树形结构，其中每个叶节点是数据块的哈希值，每个非叶节点是其子节点的哈希值。默克尔树常用于分布式系统中以实现高效的数据验证。

## Microservices（微服务）

一种现代架构模式，将应用程序拆分为独立管理的多个服务，以获得更好的可扩展性、可复用性和快速部署能力。

## Mint SVIDs（签发 SVID）

创建一个新的、可通过密码学验证的身份文档。

## Multi-cloud（多云）

使用多个云计算和存储供应商的系统架构。

## Multiregion（多区域）

跨越云平台多个区域的系统部署方式。

## Mutual TLS (mTLS)（双向 TLS）

一种密码学协议，确保客户端与服务器之间双向传输的流量既安全又可信。

## NAT (Network Address Translation)（网络地址转换）

一种在不同网络地址空间之间转换 IP 地址的方法。典型用例是允许多个设备共用单个公网 IP 地址访问互联网。

## Node/Worker（节点 / 工作节点）

在计算机系统语境下运行计算工作负载的逻辑或物理实体。节点是工作负载所运行的底层计算系统。

## Observability（可观测性）

根据系统的外部输出推断其内部状态的能力。

## OAuth

一种用于访问委托的开放标准，常用于互联网用户在不提供密码的情况下，授权网站或应用程序访问其在其他网站上的信息。

## OIDC (OpenID Connect)

构建在 OAuth 2.0 之上的身份认证层。

## OpenStack

一种虚拟机编排系统。

## OpenSSH

一套基于安全外壳协议（SSH）的工具，用于保障网络通信安全。

## OWASP (Open Web Application Security Project)（开放式 Web 应用程序安全项目）

一家致力于提升软件安全性的非营利基金会，为开发者和安全从业者提供工具、资源、教育和培训。

## Perimeter-based security（基于边界的安全）

一种安全方法：先建立强大的安全边界（例如防火墙），然后默认信任该边界内的活动或实体。

## PKI (Public Key Infrastructure)（公钥基础设施）

用于创建、管理和分发数字证书的一组策略、流程和工具。

## Proxy（代理）

位于应用程序前端、用于拦截发往该应用程序的连接的软件或设备。

## Public-key cryptography (also asymmetric cryptography)（公钥密码学 / 非对称密码学）

一种使用成对密钥（私钥和公钥）的密码系统，这些密钥具有特殊的数学性质：使用其中一个密钥加密信息后，需使用另一个密钥进行解密。此类密码学用于创建数字证书。

## Remote Code Execution (RCE)（远程代码执行）

一种安全漏洞，允许攻击者从远程服务器执行代码。

## Root of trust（信任根）

其他信任关系赖以建立的基础来源，通常指由硬件或受信任实体提供的密码学机制。

## SaaS (Software as a Service)（软件即服务）

一种软件消费模式：用户无需自行购买和运行软件，而是由服务提供商托管和维护软件。

## Scheme（方案 / 规范）

在涉及身份的语境下，指定义如何解析和理解身份的约定。

## Secure introduction（安全引入）

从密钥分发系统获取第一个密钥所面临的挑战。

## Security group（安全组）

在 AWS 语境下，安全组充当虚拟防火墙，用于控制入站和出站流量。

## Selector（选择器）

软件实体的某个属性或特征，可用于断言该实体的身份。选择器可分为节点选择器或工作负载选择器。

## Serverless（无服务器）

一种云计算执行模式，允许开发者部署代码而无需关心底层基础设施和资源分配。

## Service mesh（服务网格）

一种可配置的基础设施层，用于促进和管理服务之间的通信。

## Side-car（边车）

与工作负载并行运行的进程，以极低的侵入性为系统提供附加功能。

## Signing（签名）

添加数字签名以验证消息或文档真实性的过程。

## SIEM (Security Information and Event Management)（安全信息与事件管理）

一种使组织能够收集并分析来自应用程序、系统和网络的数据，从而检测潜在恶意活动或攻击的理念与系统。

## SLA (Service Level Agreements)（服务级别协议）

服务提供商与客户之间就服务的各个方面（如质量和可用性）达成的协议。SLO（Service Level Objective，服务级别目标）则是 SLA 中针对某项具体指标所作的约定。

## SOX (Sarbanes-Oxley Act)（萨班斯-奥克斯利法案）

美国颁布的一项旨在保护股东和公众免受会计差错及欺诈行为侵害的法案，该法案为企业带来了额外的合规性要求。

## SPIFFE ID

用于唯一标识工作负载或服务的字符串，例如 `spiffe://ukinc.com/billing/payments`。

## SSH (Secure SHell)

一种允许在客户端与服务器之间建立加密连接的协议。

## SAN (Subject Alternative Name)（主题备用名称）

受单个 SSL 或数字证书保护的备用或附加主机名。

## SVID (SPIFFE Verifiable Identity Document)（SPIFFE 可验证身份文档）

工作负载用于证明自身身份的文档。它包含一个 SPIFFE ID，目前支持两种格式：X.509 证书或 JWT 令牌。

## Telemetry（遥测）

自动收集数据点和测量指标以监控系统运行状态的过程。

## TLS (Transport Layer Security)（传输层安全协议）

一种密码学协议，通过在计算机网络上认证服务身份，在两个服务之间实现安全通信。它通常被网站用于保障 Web 服务器与 Web 浏览器之间的安全通信。

## URI (Uniform Resource Identifier)（统一资源标识符）

遵循标准语法规则、能够无歧义地标识某个资源的字符串。

## Trusted Platform Module (TPM)（可信平台模块）

一种能够安全存储密码学材料的硬件组件。

## Trust bootstrap（信任引导）

在服务或系统上建立初始信任的过程。

## Trust Domain（信任域）

对应于系统的信任根，可以代表个人、组织、环境或部门。SPIFFE 信任域是由签发机构支撑的身份命名空间。

## Web Public Key Infrastructure (Web PKI)（Web 公钥基础设施）

用于在 Web 浏览器与 Web 服务器之间的通信中实现机密性、完整性和真实性的一套系统与流程。

## Workload（工作负载）

工作负载是为单一目的、以特定配置部署的单个软件单元，可由多个运行中的实例组成，所有实例执行相同的任务。“工作负载”一词可涵盖软件系统的多种不同定义，包括：

- 运行 Python Web 应用程序的 Web 服务器，部署在前端带有负载均衡器的虚拟机集群上。
- 一个 MySQL 数据库实例。
- 一个处理队列中任务项的工作程序（worker program）。
- 一组协同工作的独立部署系统，例如使用数据库服务的 Web 应用程序。该 Web 应用程序和数据库本身也可以各自单独被视为工作负载。

## Windows

由微软开发的操作系统。

## X.509

一种广泛使用的公钥证书标准格式。此类证书被应用于包括 TLS/SSL 在内的众多互联网协议中。

## X509-SVID

SPIFFE 可验证身份文档（SVID）的 X.509 表示形式。

## Zero trust（零信任）

一种安全理念，其核心思想在于：组织不应仅凭服务运行在边界之内还是之外就自动信任任何对象，而必须在授予访问权限之前，对所有试图连接其系统的对象进行验证。
